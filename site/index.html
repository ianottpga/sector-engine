The brief

What the project set out to build

Role: expert quantitative trader, software architect and full-stack developer.

Task: design a technical and operational framework for a web application that predicts 30–90 day overall market direction and identifies top-performing sectors, using the supplied Python relative-strength script and React dashboard.

  1. Core strategy and methodology. Identify the indicators, datasets, macro drivers and technical rules, and turn them into quantifiable formulas for automated signals.
  2. Data pipeline and daily refresh. Specify data sources and APIs for index prices, sector ETFs, breadth and macro data, and an automated daily architecture to ingest closes, run the model and refresh the dashboard.
  3. Prediction engine.
    • Broad market direction: a 30–90 day Bullish / Neutral / Bearish bias with a quantitative confidence score.
    • Sector rotation ranking: relative strength, momentum and macro alignment.
    • Trade setups: top three long sectors, defensive hedges and key pivot levels.
  4. Web application. Core pages such as an executive summary, sector heatmap and backtest accuracy tracker, with the metrics and charts needed for at-a-glance decisions.

Framework

How it works, in four parts

  1. Strategy and methodology

    The supplied script ranks sectors by their return in excess of SPY over 21 and 63 trading days. That score is kept as written. The engine adds a market-direction model built from seven factors, each scaled to −1…+1 with a tanh function so no single extreme reading dominates.

    RS_n(i)      = R_n(i) − R_n(SPY)          n = 21, 63 trading days
Composite(i) = 0.40 · RS_21 + 0.60 · RS_63

    Factors and weights: trend 20%, breadth 20%, momentum 15%, risk appetite (cyclicals minus defensives) 15%, credit (HYG vs IEF) 15%, volatility (VIX level and term structure) 10%, financial conditions (Chicago Fed NFCI) 5%.

  2. Data pipeline and daily refresh

    Prices come from Yahoo Finance through yfinance: SPY, the 11 sector ETFs, RSP, HYG, IEF, VIX and VIX3M. The NFCI comes from FRED's public CSV with no API key. Polygon, Alpaca or Tiingo can replace Yahoo by changing one function.

    A GitHub Actions job runs at 21:45 UTC every weekday, after the close. It computes the signals, reruns the backtest, logs the day's call, commits the data, and redeploys the site to GitHub Pages. If the price download fails, nothing is overwritten and the dashboard flags the data as stale.

  3. Prediction engine

    BiasScore   = 100 · Σ wₖ·fₖ / Σ wₖ     Bullish ≥ +20 · Bearish ≤ −20
Confidence  = 0.55 · strength + 0.45 · factor agreement
SectorScore = 0.45·z(Composite) + 0.20·z(RS/vol) + 0.20·Trend + 0.225·RegimeFit

    Trade setups take the top three sectors that are not in a downtrend, set entries near the 20-day average, stops at two times the 14-day ATR, and targets at the larger of the monthly pivot R1 or three ATRs. The hedge is the strongest defensive sector in Neutral or Bearish regimes, or the weakest sector as an underweight when Bullish.

  4. Web application

    Six views: Summary (bias, confidence, factor drivers, six-month history, trade setups, SPY levels), Leaderboard (the original sortable table with a live 30/90 weight slider), Rotation (quadrant scatter), Heatmap, Backtest (hit rates, equity curve, calibration and a live track record), and Methodology.

Run it

Put it on a daily schedule

  1. Create a GitHub repository and push the project folder to it.

  2. In the repository, open Settings → Pages and set the source to GitHub Actions.

  3. Open Actions → Daily refresh → Run workflow for the first run. After that it runs every weekday after the close.

  4. Visit https://<your-user>.github.io/<repo>/. Swap Yahoo for a licensed feed before showing it to clients.
